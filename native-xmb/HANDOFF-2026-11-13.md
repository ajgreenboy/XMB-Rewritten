## 1. What this is

A native C++20 / Qt 6 recreation of the PlayStation 3 firmware 4.93 XMB (the cross media bar), used as a living-room
HTPC front end on Windows. It renders the XMB itself (ribbon, columns, icons, dialogs, on-screen keyboard, photo
gallery, music player) from data traced out of the 4.93 firmware, and launches Steam, emulators and web apps from it.
The pixel target is the real console: a gate compares scripted frames of the build against saved reference frames.

## 3. Build, run, verify

Build (must run in a **fresh** PowerShell process; the in-tool PowerShell fails with "vswhere not recognized", and
`-File` without `-ExecutionPolicy Bypass` fails on AuthorizationManager). The parameter is `-OutputDirectory`, not
`-OutDir`. The output "Built <exe>" means success; a failed build only prints "Native C++ build failed", so rerun
`cmake --build <out>` inside `vcvars64.bat` to see compiler errors.

```
powershell -NoProfile -ExecutionPolicy Bypass -File native-xmb\build.ps1 -OutputDirectory C:/dev/out/<name>
```

The build is MSVC /W4 and must stay at 0 warnings. Unit-test targets are separate CMake options
(`-DXMB_<NAME>_BUILD_TESTS=ON`, for example `XMB_FILE_OPS_BUILD_TESTS`); CI builds and runs all of them.

Gate (compares scripted frames with references; 27 named states plus 6 layers):

```
bun work/v2-fixtures.ts                        # once per machine / fresh worktree
bun work/ab-layers.ts --all --exe <exe>        # whole gate
bun work/ab-layers.ts --state <name> --exe <exe>
.\work\release-check.ps1 -SkipBuild            # tree hygiene: no keys, firmware or dumps
```

- Run **one gate at a time**: parallel runs collide on `C:\dev\out\v2`.
- `--save-reference` only after an intended rendering change, with the folder backed up first. Worktrees must never
  use it (their references are a junction to the real folder).
- `first-run-autologon-step` used to fail with a second display attached (an extra "Choose the Screen" first-run
  step). Fixed in `0caecce`: the state sets `XMB_SETUP_SCREENS=1`, which makes the wizard take its one-screen steps.
- `ingame-xmb` can score slightly low on one whole-frame region in a full run (Windows title-bar drift) but passes
  alone.

Scripted run (what the gate and agents use):

```
re-ps3-native.exe --dev-flash C:/dev/rpcs3/bin/dev_flash --data-dir <scratch> --vsh-modules C:/dev/xmb/fw493/vsh_module --script "full,wait,RIGHT,DOWN,ENTER,pause=ms,TRIANGLE,grab=C:\path\x.png,quit"
```

Set `TEMP` under `C:\dev\out`, `XMB_SINGLE_INSTANCE=0`, `XMB_STEAM_ARTWORK=0`, `XMB_STEAM_ACTIVITY=0`, and
`XMB_POWER_DRY_RUN=1` for any power path (`XMB_AUDIO_DRY_RUN=1` for audio; `XMB_LOG=<file>` for the log). The Friends
column is 3x RIGHT from start; with Discord signed out, DOWN x6 reaches the Discord rows. **Never press Cross on game
tiles, Steam account rows or Open-URL rows in a scripted run** (see section 7).

## 7. Rules and gotchas

- **Never press Cross on game tiles, Steam account rows or Open-URL rows in a scripted run.** Agents did this in
  this stretch: one launched Steam app 202970 (Call of Duty: Black Ops II; no game process appeared), one opened
  discord.com, one opened the "Switch Steam Account" prompt (nothing confirmed). Use dry-run env vars for anything that
  acts on the live system.
- Two scratch files (`RR-Probe-Delete-Me (2).wav`, `outside.wav`) are in the owner's Recycle Bin; they should delete
  them (shell removal hung PowerShell).
- Never stop processes by name, only PIDs your own test started. Never touch the real `re-ps3-native-kiosk` task or the
  real Start menu. Test power, audio, autostart and file deletes only with dry runs, scratch names, or scratch folders.
- Claims in docs are labelled TRACED (cite module/address/RCO), measured, or INFERRED.
- Never in the repo: firmware, extracted assets, captures, dumps, keys, account data, names, emails or LAN addresses.
- Tooling: Bun/TypeScript for helpers; no Python, no npm/npx.
- Windows: Qt `canonicalFilePath` does not follow junctions; `GetFinalPathNameByHandleW` does.

## 8. Worktree workflow for parallel agents

1. Agent works in `C:\dev\xmb-wt\<n>` on branch `wt/<n>`, commits as `Al`, does not push. `out\native-reference` is
   linked by a junction (`cmd /c mklink /J`): it must never save references.
2. Land: `git log origin/main..wt/<n>` (check author, no AI mentions); cherry-pick or fast-forward onto
   `origin/main`; expect small conflicts in `CMakeLists.txt` source lists and phase-plan tables (keep both sides);
   build, run the affected states (`--state <name>`), the full gate for rendering or startup changes; then
   `git push origin HEAD:main`.
3. Clean up: remove the junction **first** with `[IO.Directory]::Delete(<link>, $false)`; then
   `git worktree remove --force`. If Windows says "Permission denied", wait a few seconds and
   `Remove-Item -Recurse -Force`. Afterwards check the reference count is still 99,706.
4. Other worktrees that still exist: `C:\dev\xmb-wt\gatefix2` (old integration, detached `5c5f390`) and the scratch
   folder `C:\dev\out\a2-head` can be removed once nobody needs them.
5. Subagents: cheapest model that can do the job, always passed explicitly (Haiku mechanical, Sonnet normal coding,
   Opus only for hard work). Agents hit the 5-hour usage limit twice; their worktrees kept the work and they were
   resumed after the reset.
